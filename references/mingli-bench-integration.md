# MingLi-Bench 整合评估（BFFT v7.5）

> 来源：小红书《算了一辈子命的师傅，可能真要失业了》→ Tianfu Agent（tianfuagent.com）
> → 开源仓库 [DestinyLinker/MingLi-Bench](https://github.com/DestinyLinker/MingLi-Bench)（MIT）

## 1. Tianfu Agent 是什么

DestinyLinker 团队研发的命理 Agentic 系统，技术报告称其在 2025 年全球算命师大赛
（HKJFMA 主办，3069 名有效参赛者）官方题库上取得 **50% 截尾准确率**（5 轮多数投票），
超越最佳通用大模型基线（Claude Opus 4.6，40%），逼近人类 Top20 平均（53.5%）。
四选一选择题的随机猜测线是 25%。

核心架构（据技术报告）：

| 设计 | 内容 |
|---|---|
| 确定性计算工具 | 200+ 原子工具：排盘、时间推演、空间路径（飞宫）等可精确计算的方法 |
| 四级工具可见性 | 自动注入型（十神/星耀/宫位，零歧义概念直接注入）/ 按需调用型（生克/飞宫，模型自行判断参数）/ 转译调用型（非通用术语，预设翻译层）/ 触发注入型（仅特定 Sub-Agent 可用，配专属知识库） |
| 规则函数化 | 每条复杂规则封装成带元数据的可调用函数（人类专家标注适用场景/时间跨度/事件类型/优先级），接受命盘状态，返回结论+置信度 |
| 多 Sub-Agent 协作 | 各 Sub-Agent 维护独立工具集与上下文，渐进式发现策略展开推理 |
| 三层不确定性量化 | 工具输出层（内置算法置信度）/ Sub-Agent 层（LLM 自评显著性）/ 多流派合参层（人工经验置信度加权调和矛盾） |

**开源现状**：Tianfu Agent 本体（工具库/规则库/Sub-Agent 编排）**未开源**。
公开的是评测基准 MingLi-Bench：160 道 2022—2025 大赛官方真题（四选一，带标准答案、
出生信息、类别标注）、iztro 预计算盘（紫微斗数 + 八字四柱）、以及一套调各家 LLM
API 的评测 CLI（需要 API key）。

| 资产 | 位置 | 说明 |

| 160 题真题数据 | `data/mingli_bench/data.json` | 2022—2025 大赛题（MIT 许可），类别：婚姻 44 / 事业 25 / 家庭 22 / 健康 17 / 性格 14 / 财运 13 / 学业 11 / 子女 6 / 外貌 3 / 运势 2 / 灾劫 2 / 官非 1 |

## 3. 排盘交叉验证结果（160 例，tz=+8 对齐 iztro 口径）

| 指标 | 结果 |
|---|---|
| 四柱全同 | 150 / 160（93.8%） |
| 月柱 / 日柱 | **160 / 160（100%）** |
| 年柱 | 155 / 160（96.9%） |
| 时柱 | 155 / 160（96.9%） |
| 海外案例（usa/japan/malaysia/singapore/china 5+5+40+5+5） | 60 / 60（100%） |

10 例不一致**全部可归因，无 BFFT 排盘错误**：

| 组 | 差异 | 归因 |
|---|---|---|
| ftb_0011—0015（5 例，女命 1990-05-23 17:30 中国大陆） | 时柱 辛酉(iztro) vs 庚申(BFFT) | **中国夏令时口径差异**：1990-05-23 在 1986—1991 夏令时窗口内，BFFT 按 `--dst auto` 回拨 1 小时（17:30→16:30 申时），iztro 不回拨（酉时）。BFFT 行为与出生记录口径相关，属已知边界（SKILL.md guardrail：1986—1991 出生者须确认记录是否已扣夏令时） |
| ftb_0151—0155（5 例，女命 1988-02-15 16:50 台湾） | 年柱 丁卯(iztro) vs 戊辰(BFFT) | **农历年 vs 立春年流派差异**：1988-02-15 是农历丁卯年腊月，iztro（紫微斗数惯例）按农历年定年柱，BFFT 按八字惯例以立春定年柱（1988-02-04 立春已过 → 戊辰）。紫微/八字流派差异，非错误 |

**结论**：BFFT 排盘在 160 例真实大赛案例上与 iztro 完全一致（排除口径差异后 ≈ 100%），
月柱日柱零差异。此前 famous20 只有 20 例，此基准把外部排盘验证扩展到 160 例。

## 4. 推理盲测（BFFT 盘面 + 规则摘要 → 四选一）

**结果：9/20 = 45.0%（随机基线 25%，差距 +20%，标准误 ±9.7%，约 2 SE，边缘显著）**

方法：从 160 题排除 10 例口径差异题后随机抽 20 题（seed=7），每题注入 BFFT 排盘
盘面摘要（四柱/十神/五行计数/十二长生/大运表/25 年流年表）+ 核心规则摘要
（十神定义、身强弱、用神、岁运冲合、伏吟返吟、岁运并临），由 LLM 做四选一判断。
与 Tianfu 报告基线设置对齐（prompt 提供预计算盘面，隔离"排盘正确性"，只测推理）。

| 参照 | 准确率 |
|---|---|
| 随机猜测线 | 25% |
| 通用大模型基线（Tianfu 报告：Claude Opus 4.6 等，5 轮多数投票） | 23%—40% |
| **BFFT 盲测（本试点：flash 模型 + 规则摘要，单轮）** | **45.0%（9/20）** |
| Tianfu Agent（200+ 工具 + 规则函数化 + 多 Sub-Agent，5 轮多数投票） | 50% |
| 2025 大赛人类 Top20 平均 | 53.5% |

按类别：健康 2/2、性格 2/3、事业 1/2、财运 1/3、家庭 2/5、婚姻 1/5。

诚实解读（不夸大）：
1. **样本只有 20 题**，95% 置信区间约 [26%, 64%]，不排除运气；组间波动大
   （A 组 3/10 = 30%，B 组 6/10 = 60%）。
2. 本试点用的规则摘要（约 500 字）远非完整 BFFT 规则库（SKILL.md + 六份 references），
   也未做 5 轮多数投票；这不是"BFFT 完全体"的成绩，而是"盘面 + 精简规则"的下界。
3. 婚姻类 1/5 最弱——大赛婚姻题的选项常依赖"宫位 + 十神 + 具体流年"多层叠加，
   精简规则摘要下模型缺乏这类复合判断的抓手。
4. 单轮 45% 落在"通用模型之上、Tianfu 之下"的区间，与 Tianfu 报告的结论互相印证：
   **工具化规则承载（规则函数化 + 分级注入）确实能显著提升专业推理准确率**，
   BFFT 的规则目前仍靠模型读取记忆，正是差距所在（见 §5）。
5. 复现：`python scripts/mingli_bench_pack.py --count 20 --seed 7`
   → `python scripts/mingli_bench_score.py data/mingli_bench/results/mingli-pack-ans.json --answers ...`
   盲测包与答案/评分明细保留在 `data/mingli_bench/`（`mingli-pack.json` 无答案版、
   `mingli-pack-ans.json` 答案版，`results/answers-a.txt` / `answers-b.txt` 原始作答、
   `results/mingli-pack-ans.bfft-20.json` 评分明细、`results/mingli-verify-detail.json` 160 例排盘比对明细）。

## 5. BFFT vs Tianfu Agent 架构差距

| 维度 | BFFT（现状） | Tianfu Agent | 差距评估 |
|---|---|---|---|
| 确定性排盘 | ✅ `pai_pan.py`（真太阳时/夏令时/换日/历法） | 200+ 原子工具 | BFFT 排盘部分更强（真太阳时+ΔT+历法声明），但只有单一 CLI，无工具分级 |
| 工具管理 | ⚠️ 无（模型直接调 CLI，工具少不存在选择问题） | 四级可见性动态注入 | 若未来扩工具集（飞宫/神煞矩阵/大运细化），需要引入分级；当前工具数 <10，不构成问题 |
| 规则承载 | ⚠️ 规则在 SKILL.md/references（LLM 读取遵循） | 规则函数化（可调用、带元数据、返回置信度） | BFFT 的断语三级制（S/C/X）+ 门派并列是"规则元数据"的雏形，但未函数化；长上下文下模型确实可能选择性忽略规则 |
| 多流派合参 | ✅ 门派分歧并列输出（换日/胎元/强弱） | 多 Sub-Agent + 人工经验置信度加权 | BFFT 并列但不加权；Tianfu 的"置信度加权调和"值得借鉴 |
| 不确定性量化 | ✅ base_rate + Brier + 技巧分数（更强） | 三层置信度（自评） | BFFT 的可证伪体系（事前登记+基线+技巧分数）严格强于 Tianfu 的自评置信度 |
| 验证手段 | ✅ 62 条不变量测试 + 事前登记 | 无（报告坦承缺乏验证手段） | BFFT 更强 |
| 推理评测 | ⚠️ 此前无外部题库 | MingLi-Bench 160 题 | 本次整合补上：排盘交叉验证 ✅ + 盲测 ✅ |

## 6. 路线图（建议）

1. **盲测常态化**：把 MingLi-Bench 160 题纳入发布前检查（类似 verify.py），
   季度跑一次盲测（可先 20 题子集），准确率记录进 CHANGELOG。
2. **规则函数化试点**：把 M5 时序引擎的几条高冲突规则（岁运并临/伏吟返吟/征太岁）
   封装成可调用函数（输入盘面+流年，输出结论+置信度），对齐 Tianfu 的规则函数化。
3. **工具分级**：若后续新增飞宫/大运细化工具，按 Tianfu 四级可见性设计，
   避免工具选择退化。
4. **多流派加权**：换日两派/胎元两派目前并列；可试点"流派置信度加权合参"
   （如 zi/midnight 两派各给一个结论置信度，加权输出）。
5. **紫微整合（远期）**：fortune_api_results.json 含完整紫微斗数十二宫位星曜数据，
   与 BFFT 的八字体系是平行体系（SKILL.md 已引《果老星宗》作平行参照），
   暂不并入主推理链。
